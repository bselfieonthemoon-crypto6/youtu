# Loomic 全项目审计与大改造总计划

> 日期：2026-08-31  
> 状态：第一轮代码审计、P0 底座修复、Agent 可控化与供应商后台第一阶段已实施（更新于 2026-09-01）  
> 目标：先保证数据不丢、权限不越界、任务可恢复，再逐项建设产品能力。

## 1. 结论先行

Loomic 已经具备登录、项目、无限画布、Agent 对话、图片/视频生成、品牌套件、Skills、积分和多模型接入的主体框架，但还没有形成稳定的生产闭环。

本次审计的核心判断：

1. 当前最重要的不是继续增加模型，而是保证画布中的生成结果不会被并发写入、同步或新生成覆盖。
2. 新生成、修改、替换、删除必须成为四种不同操作。默认只能新增。
3. 浏览器、Agent、图片 Worker、视频 Worker 的画布写入必须全部经过同一套版本合并协议。
4. Agent 的自然语言决定不能直接等同于用户授权。删除、扣费、Shell、跨项目访问必须由代码强制限制。
5. 画布是当前产品的最终内容来源：用户明确从画布删除即视为删除；除此之外，任何系统行为都只能追加或修改明确目标，不能让旧图消失。
6. 在 P0 完成之前，不建议快速堆叠协作、PSD、3D 等新功能，否则数据丢失、重复扣费和越权面会继续放大。

## 2. 当前系统全链路

```text
用户
  ↓
Next.js Web
  ├─ Supabase Auth
  ├─ Home / Projects / Settings / Skills / Brand Kit
  └─ Excalidraw Canvas + Chat Sidebar
       ↓ REST + WebSocket
Fastify Server
  ├─ JWT 鉴权 / Viewer / Workspace
  ├─ Project / Canvas / Chat Session
  ├─ Agent Runtime
  │    ├─ LangGraph thread/checkpoint
  │    ├─ Deep Agent
  │    ├─ 主模型路由
  │    ├─ Canvas / Image / Video / Brand / Skill tools
  │    └─ 流式事件与事件回放
  ├─ Generation Orchestrator
  │    ├─ Tier / Credits
  │    ├─ background_jobs
  │    └─ PGMQ
  └─ Supabase
       ├─ Postgres + RLS
       ├─ Storage
       └─ LangGraph persistence
            ↓
Worker
  ├─ Claim job
  ├─ 调用图片/视频供应商
  ├─ 保存结果到 Storage / asset_objects
  ├─ 更新任务和积分
  └─ 插入画布元素并发送 canvas.sync
```

## 4. Agent 运行逻辑

### 4.1 每轮运行

1. WebSocket 连接使用 Supabase 用户身份建立。
2. `agent.run` 传入 session、conversation、canvas、prompt、附件、模型偏好和 mentions。
3. 服务端验证用户、会话和画布归属。
4. 服务端解析工作区默认模型、品牌套件和启用的 Skills。
5. 读取当前画布，生成 `<canvas_state>` 摘要。
6. 创建 LangGraph/Deep Agent，加载 checkpointer 和 store。
7. Agent 自主选择工具并流式返回事件。
8. 事件写入内存回放缓冲区，同时持久化聊天消息和 run 元数据。
9. 生成任务进入后台队列；Worker 完成后保存资产、插入画布并触发同步。

### 4.2 工具职责

| 工具 | 职责 | 边界 |
|---|---|---|
| `inspect_canvas` | 获取精确画布元素 | 只读 |
| `screenshot_canvas` | 视觉验证 | 通过浏览器 RPC 截图 |
| `manipulate_canvas` | 操作结构化元素 | 删除必须来自本轮用户明确指令 |
| `generate_image` | 创建图片任务 | 默认新增，不得替换旧图 |
| `generate_video` | 创建视频任务 | 必须走 Job/积分/Worker |
| `get_brand_kit` | 获取品牌上下文 | 只读品牌资产 |
| Project Search | 查找项目资料 | 应保持工作区隔离 |
| Files/Skills | 读写 Agent 工作文件 | 生产环境不得访问主机 Shell |

### 4.3 新增、修改、替换、删除规则

```text
“再生成一个 / 换个风格 / 做简约版” → ADD VARIANT
“修改这张图的文字/颜色”          → EDIT TARGET
“用新版替换旧版”                 → ADD NEW + DELETE OLD（必须明确指定旧元素）
“删除这张旧图”                   → DELETE ELEMENT（从画布及文件列表消失）
```

强制不变量：

- 生成工具永远只能新增画布元素。
- Agent 没有用户本轮明确删除指令时，后端拒绝 `delete`。
- 用户明确删除画布节点后，该内容在产品中视为已删除；底层 tombstone 仅用于并发合并，后续可由后台安全回收存储文件。
- 重新生成必须创建新的元素，不能复用旧元素 ID 或覆盖旧文件引用。
- 所有危险操作必须有明确 target ID，而不是依靠模糊文字猜测。

## 5. 本轮已经完成的底座修复

### 5.1 生成结果不再被并发覆盖

- 浏览器自动保存：保留 Excalidraw 删除墓碑。
- 浏览器关闭/卸载保存：与普通自动保存使用相同语义。
- 浏览器收到 `canvas.sync`：按元素 ID 和 version 合并，不再全量覆盖本地未保存元素。
- HTTP 保存：读取最新内容、合并、`updated_at` 条件更新、冲突重试。
- 图片/视频 Worker 插入：CAS + 重读重试。
- Agent `manipulate_canvas`：CAS + 基于最新画布重新执行。

### 5.2 Agent 不再自行清理旧生成结果

- 系统提示词规定：新生成默认只能追加，不能覆盖或自行清理旧结果。
- 原始用户消息随运行配置传入工具层。
- 没有明确删除意图时，即使模型调用 delete，也会被后端拒绝。
- “不要删除”“保留旧图”等否定指令会优先阻断删除。

### 5.3 生产安全边界

- REST Agent Run 现在强制认证。
- Run cancel 校验运行所属用户。
- WebSocket 不再接受客户端替换 access token。
- `canvas.resume` 和带 canvas 的 `agent.run` 在绑定/回放前验证画布归属。
- 生产 Agent backend 从 `LocalShellBackend` 改为 `StateBackend`，不再暴露主机 Shell。
- 只有开发隔离目录存在时才注册本地文件持久化工具。
- 视频子 Agent 统一走 Job/积分/Worker/Storage 路径。
- 新增数据库迁移，把积分变更 RPC 限制为 `service_role`。
- 上述积分权限迁移已应用到当前 Supabase，并验证匿名/普通登录角色无执行权限。
- 每个生成 Job 的退款增加数据库唯一约束，重复退款会连同余额更新一起回滚。

### 5.4 Job 取消和重试状态机

- Worker 只有原子认领 `queued/failed → running` 成功后才调用 Provider。
- `canceled` 是不可覆盖终态，不能再变成 succeeded/failed/dead letter。
- 重复队列消息或已取消任务不会增加尝试次数，也不会调用模型。
- 取消竞态后任务归档并执行幂等退款。
- 成功、失败、取消和重复退款路径已有回归测试。

### 5.5 工程基线

- 移除根测试对不存在 `apps/desktop` 的错误要求。
- 补齐 `langgraph` schema 的共享数据库类型。
- 类型生成命令改为同时包含 `public,langgraph`。
- 为画布合并、CAS、删除保护和浏览器合并新增测试。

### 5.6 Agent 可控化第一阶段（2026-09-01 已完成）

- 复用 Deep Agents 的 `write_todos`，转换为产品级 `plan.updated` 全量快照；计划按版本更新，断线重放不会堆叠旧步骤。
- 聊天中显示“执行计划”和待执行、执行中、已完成、失败状态；最终计划随助手消息持久化，刷新后仍可查看。
- 工具执行状态区分运行、完成、失败和取消，并继续展示真实输入参数、模型和工具输出。
- 运行中的发送按钮切换为停止按钮；正常运行、ACK 前取消和断线恢复后的运行均可取消。
- 删除不再由关键词直接授权：任何包含 `delete` 的整批操作先冻结为提案，确认前画布零写入。
- 删除确认绑定用户、画布、目标 ID、目标版本、级联文字、两分钟有效期和一次性状态；过期、跨用户、重复点击或目标漂移全部拒绝。
- 只有产品原生确认卡的“确认删除”按钮能够执行被冻结的提案；聊天文字和模型工具参数都不能自行授予删除权限。
- 确认删除后广播 `canvas.sync`；取消时画布保持不变。新生成结果仍只追加，不覆盖旧图。

### 5.7 Agent 可控化第二阶段核心能力（2026-09-01 已完成）

- Run 协议新增闭集 `executionMode: fast | thinking`；旧客户端省略时由服务端统一按 Fast 执行。
- Web 输入区可切换 Fast / Thinking 并本地记住选择；HTTP 与 WebSocket 都完整传递该模式。
- Fast 强调直接高效，Thinking 强调规划和关键验证；两者都保留可见计划，但都不展示或编造隐藏思维链。
- Google AI Studio 按模型能力使用供应商原生 thinking 配置：仅确认支持关闭思考的 Gemini 2.5 Flash/Flash-Lite 在 Fast 使用 budget 0；Gemini 2.5 Pro、Gemini 3.x 和未知未来模型保持原生动态策略，避免发送不支持的参数。OpenAI 兼容、APIYI 和 Vertex 路径同样不发送猜测参数。
- Agent 图片/视频任务改为“先建任务但不入队 → 服务端扣积分并绑定账务 → 回查余额 → 入队”，Worker 不会在扣款成功前调用 Provider。
- 扣款后、入队前任一步失败都会取消未执行任务，并按 Job ID 对已扣积分发起幂等退款；Agent 运行取消会同步取消正在等待的生成 Job。
- 普通图片/视频 Job HTTP 接口也使用相同的“扣款成功后再入队”顺序，不再保留可被 Worker 抢先执行的旧路径。
- 用户取消 Job 后服务端会按 Job 账务记录立即尝试幂等退款，不再只依赖 Worker 以后重新看到队列消息。
- Agent 在建任务、扣款和入队的关键边界重复检查取消信号，避免用户已经停止后仍继续扣费或发布任务。
- 生成工具返回服务端权威账务摘要：预计积分、实际已扣积分和扣款后余额。前端直接展示该摘要并立即同步全局余额，不再自行计算实际费用。
- 退款状态暂不由前端或任务状态推测；只有账本确认后才能显示“已退”。

### 5.8 安全重试边界（已定稿并实施第一阶段）

- 纯读工具可以基于原执行账本精确重新读取，并用请求 ID 防双击和断线重复执行；首版只开放 `inspect_canvas`。
- 图片/视频生成只能复用原 `jobId` 继续等待或恢复结果；不得重新调用 Provider、不得再次扣费（已完成）。
- 画布写操作当前不自动重试，尤其禁止重放新增、删除和混合操作。
- 在服务端没有执行检查点前，不把“重新发送整段提示词”包装成“继续后续步骤”。
- 只有服务端工具执行账本、Job ID 持久化和画布插入幂等键齐备后，才开放对应操作按钮。

### 5.9 Agent 安全恢复与工具执行账本（2026-09-01 已完成首版）

- 新增服务端写入的 `tool_executions` 权威账本，记录 Run、Tool Call、输入、输出、状态、是否可重试、尝试次数和重试来源。
- 数据库只允许工作区成员读取自己的执行记录；普通登录用户不能写入或篡改账本。
- 工具失败有独立 `tool.failed` 事件，不再只能依赖整轮 `run.failed`；运行取消/失败时会收口仍在运行的账本记录。
- `agent.retry_tool` 只接受服务端账本执行 ID 和客户端幂等请求 ID，不接受工具名、输入或画布 ID；首版服务端硬编码只允许失败的 `inspect_canvas`。
- 相同 request ID 重发只返回原执行状态，不会重复读取；跨用户、非失败记录和副作用工具全部拒绝。
- 聊天失败卡会显示“重新读取”，成功结果作为新的 ToolBlock 持久化，刷新后仍可查看。
- 图片和视频画布元素写入 `sourceJobId`；CAS 写入前按未删除的同源元素查重，重复恢复返回原元素。
- 新增原 Job 恢复接口：仅允许任务所有者恢复已成功且结果完整的任务；只读取原任务结果并补回画布，不调用 Provider、不扣积分。
- 生成卡片在超时/仍运行时显示“继续等待”，成功但尚未落画布时显示“恢复到画布”；同一 Job 共用轮询并防双击。
- `tool_executions` 迁移已经应用到当前 Supabase。

### 5.10 Agent 计划关联与运行历史（2026-09-01 已完成核心链路）

- `write_todos` 只有在工具成功结束后才提交计划快照；失败的计划草稿不会出现在产品界面。
- 计划步骤 ID 在同一 Run 内保守复用：唯一同名步骤可跨版本保持，重命名、重复标题或歧义场景分配新 ID，禁止按数组位置伪造身份。
- 只有最新已提交计划中恰好一个 `in_progress` 步骤时，普通工具才会获得 `planId + planStepId`；关联在工具开始时冻结，完成或失败时不会被后续计划推进改写。
- `tool_executions` 已持久化计划关联；精确重试继承原关联。数据库约束要求两个关联字段同时存在或同时为空。
- 聊天计划步骤下会显示真实关联工具及运行、成功、失败、取消状态；点击可精确定位完整工具卡并短暂高亮。没有服务端关联的工具只保留在执行时间线，前端不猜。

## 12. 当前实施方向：画布业务优先

图片批量生成暂缓：后续由用户在生成前自行选择张数，不采用预设 2/5/10 固定档位；待确认交互、范围、套餐限制和计费规则后，再补对应并发与刷新 E2E。无论最终选择多少张，新图都只能追加，不能覆盖旧图；用户主动从画布删除后不建设永久资产中心恢复入口。

积分 RPC、支付回调幂等、私有用户资源桶、安全 GC、附件与 Provider 下载安全已经达到当前开发阶段所需的基础线。运行时资源上限、工作区限流、Generation Orchestrator 合并等数据层与运维层优化暂缓，不阻塞画布业务验证。

接下来按用户实际操作链路推进：

1. 先接通图层锁定、隐藏/显示等已经露出的画布控件，并清理无行为的占位按钮。
2. 补齐 Frame 与大型画布导航，让生成内容可以被组织、定位和选择。
3. 推进局部编辑、裁剪、擦除、扩图、去背景等高频图片编辑业务。
4. 补齐画布导出和多尺寸适配。
5. 最后再回到对象历史、版本恢复、运行时限流及其他生产级加固。

画布业务的统一约束保持不变：生成结果只追加；新图不得覆盖旧图；用户主动删除后即从画布业务中消失；隐藏图层不得被当作删除处理。
