## 问题清单

### 1. P1：没有执行却声称已提交/已完成【真实复现】

这不是供应商失败：本轮根本没有调用生成工具，也没有持久任务。现阶段只能确认执行事实与自然语言回复没有可靠对齐，不能把“摘要污染”或“某个模型错误”断言为唯一根因。

相关边界：`apps/server/src/agent/mastra-agent.ts:90` 的流式执行与 `apps/server/src/agent/mastra-run-integration.ts:24` 的生命周期检查。生命周期完整不能证明图片请求被执行，提示词里的“不编造任务号”也不能替代真实回执。

### 2. P1：历史摘要成为正常对话的单点故障【真实复现】

`mastra-runtime.ts:209` 同步等待摘要再进入主 Agent；`mastra-context.ts:246-260` 的二次摘要为空或超过字节上限时直接抛错，没有保留有效旧摘要/近期消息的降级路径。日志只能证明二次校验失败，不能区分空结果还是超限。系统指令的词数、生成 token 上限和应用 UTF-8 字节上限也不是同一种约束。

不能说会话已永久锁死：本轮后续只读提问恢复成功。但一次摘要问题足以让清晰用户请求直接失败，且前端只得到通用错误。

### 3. P1：比例修订仍经过旧式硬拦截【函数实测】

直接调用现有纯函数，未发模型/图片请求，结果如下：

- `把原来的3:4竖版改成16:9横版` → `ambiguous: true`。
- `不要1:1，改为16:9` → `ambiguous: true`。
- UI 选 1:1，文字提 9:16 → `image_aspect_ratio_conflict`，而当前主 Agent 指令称明确 UI 选择优先。

位置：`tools/image-generate.ts:59-90,119-135`；旧测试 `tools/image-aspect-ratio-enforcement.test.ts:222` 甚至把这类明确修订的拒绝写成期望结果。本轮真实请求被摘要失败/无工具误报先挡住，不能说已经真实触发了比例工具拒绝。

### 4. P1：编辑不显式传比例时，服务端会退回方图【代码确认，未做额外付费复现】

规范化允许带源图的 edit 请求省略 aspectRatio；`mastra-image-tool.ts:310` 随后固定补为 1:1，没有从真实源图尺寸继承。模型主动填写 3:4 时能成功，不等于“继续修改但不提比例”已有服务端保障。

### 5. P1：Auto 的能力选择没有闭合到实际输入要求【代码确认＋已有渠道失败证据】

`mastra-runtime.ts:117` 只提供通用 image_generation 目录，`tools/image-generate.ts:341` 在 Auto/省略时最终可取默认或首项；不是基于当前编辑能力、参考图数量和比例可靠性的完整选择。已修复的唯一模型别名映射不等于 Auto 路由已经可靠。

上轮已证明当前 Nano 非方形输出失败；本轮未再次付费重复该故障。这里只报告 Auto 仍可能选到不适配渠道的链路缺口，不把 GPT 成功当作 Nano 修复。

### 6. P2：相关图窗口与最新修正可能断链【代码风险，完整边界实测未覆盖】

- 运行开始时的最近十个成功 job 与候选 manifest 被冻结；更早的原生设计图、同轮刚生成的原生设计图，未必能经后续显式资产解析重新纳入。顶层画布有实时回退读取，原生设计内部来源没有同等保障。
- 显式 job UUID 补充诊断回执，不等于补充可编辑来源。
- `mastra-image-source-grounding.ts:296-300` 会跳过超过剩余预算的最新长用户消息，再装入更旧的短消息；可能把最新 A→B 修正丢掉，却保留旧 A。

本轮旧绿色 Logo 回溯成功，只证明仍在候选范围内的旧图可用，不覆盖超过窗口、已从外层画布移除等情况。

### 7. P2：每步工具增长缺少整个请求的总预算检查【代码风险，未真实压到超限】

`mastra-agent.ts:38-49` 按字符串/数组成员裁剪，而非按整条工具结果总量限制；`prepareStep` 仅更新 activeTools。初始历史压缩不能约束后面多次技能/设计查询积累的内容。单个字符串不大，不代表整个模型请求不大。
