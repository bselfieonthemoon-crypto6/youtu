# 对话生图可靠流程交付记录

日期：2026-09-07。改动前基线：`c62e082`。

## 交付范围

覆盖通过对话生成到无限画布和原生设计画板的主流程。不更换供应商、不改写绘图编辑器，不绕过已有工作区授权、模型访问或分辨率限制。

流程：需求 → 持久化方案 → 明确确认当前版本 → 唯一任务 → 原子扣费与入队 → Worker → 图片资产保存 → 目标落图 → 对话与画布刷新。

## 改动

1. **方案持久化**：新增 `image_generation_proposals`，保存冻结参数、来源轮次、所属用户/对话/画布、状态和有效期（24 小时）。不保存访问令牌或 API Key。应用重启后可读取同一方案。
2. **修改保护**：新方案取代待确认旧方案；识别到常见修改指令时，先作废待确认方案，再进入 Agent 规划。不能用上一次“可以”自动批准后来才出现的结构化方案。
3. **确认边界**：前后端共用严格确认词表。否定和夹带修改的确认不会执行。按钮提交真实方案 ID 与当前 session，不再调用保存内存闭包的旧确认接口。破坏性画布/模板确认保持原接口。
4. **确定性确认入口**：“确认生成”等明确指令和确认按钮直接进入产品执行路径，不再依赖语言模型重新规划、重新拼装生成参数。模糊回复仍由对话 Agent 理解，确认工具仍执行严格校验。
5. **运行上下文**：执行使用确认这一轮的身份、运行状态和任务提交器，不复用方案提出时的取消信号/闭包。
6. **目标绑定**：同一对话的画板生图后续不能静默退回无限画布；首次提交前重新检查工作区、画布归属及画板 revision。已有任务的重复确认不因后续画板版本变更而重新生成。
7. **参数保护**：参考图无法解析时拒绝方案，不静默删除参考图；无限画布坐标/尺寸进入规范化 target；新的画板方案使用新的操作幂等键，重试沿用冻结键。
8. **任务幂等**：方案 UUID 同时用作图片任务 UUID，数据库主键防止重复创建；已存在任务优先读取，不重复生图。任务消息和占位节点避免重复写入。
9. **扣费与入队事务**：服务端冻结可收取额度；受限 RPC 在同一事务中锁任务、执行幂等扣费、发送 PGMQ 消息、记录入队时间。入队失败整笔事务回滚；丢失响应不会触发盲目取消/退款。
10. **提交恢复**：Worker 每 30 秒独立扫描已确认且创建超过 60 秒的未入队任务；与历史图片落图扫描隔离，避免慢扫描阻塞。无法恢复时记录明确失败，不无限显示生成中。
11. **展示恢复**：正常 queued/processing 任务也启动补查，刷新加载历史消息后可恢复补查。图片接口 succeeded 与实际落图分开判断；画布等待元素 ID，设计画板等待最终聊天结果记录。后台任务完成不要求 Agent 对话轮次保持打开。

## 使用与边界

- 给出设计需求，查看方案后点击“确认方案，继续生成”或回复“确认生成”。需要改动时直接说出修改要求，等待新方案再确认。
- 刷新不会新建图片任务；已有任务重复确认不重新生成。想要额外一张，应明确提出新的生成需求并确认新的方案。
- 部署前旧内存方案无法迁移成完整冻结参数；遇到旧方案失效，重新提出方案后确认。已保存图片和已有后台任务不删除。
- 生图期间人为修改画板导致替换冲突时，继续使用原有 `needs_attention` 保护，不强行覆盖其他图层。
- 供应商不可用、限流、断网、存储或数据库长时间不可用不能保证成功；本次保证的是可恢复的任务记录、边界校验和可观察状态，不承诺“永无 Bug”。轮询超过 10 分钟仍保留任务及手动等待入口，不自动重生成。
- 常见修改指令保护不是完整自然语言理解器；复杂语义仍需要 Agent 生成供用户查看的冻结方案。最终确认应以方案为准。
- 发现一条 9 月 1 日创建、9 月 5 日最后更新的历史 running 任务，未擅自清理或退款；新恢复逻辑仅处理本次持久化方案产生的提交窗口，不追溯改写旧任务。
