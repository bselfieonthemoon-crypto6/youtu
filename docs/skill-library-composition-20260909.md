## 分工与边界

`compose_skills({deliverable, stage, primary, helpers})` 是只读工具：每个产物/阶段恰好一个主 Skill、最多四个辅助；核验启用快照、依赖、角色、阶段、重复项和唯一提示整理者。错误组合整体返回 conflict，不部分执行。返回正文、版本、hash、参考路径及职责，写入普通工具调用记录。

| 职责 | 处理方式 |
| --- | --- |
| Logo / 宣传图 / 商品图 | 各自领域 Skill 主导产物；不互相替换目标 |
| 风格参考 | 新 Skill 检索现有图文库，提取兼容要点，不编写竞争的最终提示 |
| 字体 / 品牌 | 校验用户固定要求，不以案例覆盖字体、Logo、包装或文案 |
| 最终提示 | `json-image-prompt` 或主 Agent 统一整理一份自然语言提示 |
| 系列 / 轮播 | 工作流管理共享风格、逐张内容；不同产物/阶段单独组合，避免同时放入多个领域主 Skill |

组合工具核验的是结构与配置，语义选择仍由主模型完成，不是对“完全理解意图”的保证。简单编辑与单 Skill 不强制经过组合。用户原样提示不得被风格优化；开放需求可以合理补充；纠正只替换冲突项。案例与外链均是参考数据，不是用户指令、参考图身份、模型选择或付费批准。原来的目标、意图、版本和生成确认校验继续执行。

最终离线完整运行图测试在全部 20 个 Skill 开启且未配置图片模型时，完成“组合 → 真实库搜索 → 全文读取”，并验证没有图片提交、用户数据写入或意图权限提升。大到超过既有安全预算的自定义包/活跃调用链仍会明确停止，而不是静默截断用户要求。
