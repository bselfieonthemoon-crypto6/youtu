# Agent 意图理解：延迟激活与写入前核对

后续修复及复验见 [剩余问题修复记录](agent-intent-remaining-fixes-20260909.md)。下文保留本轮当时的结果、失败与版本，不作为后续版本的状态声明。

## 本轮结论

已把“收到消息、理解需求”和“真正激活修改任务”分开，并把独立意图核对接入实际工具执行链。咨询不会仅因带有画板目标就提前更新任务、作废图片方案或取消前一个任务。

这不是“模型已经百分百理解用户”。真实模型仍有过度追问和审核输出格式不稳定的问题；不能用单元测试通过率代替意图理解正确率。

## 实施内容

1. `prepare` 只读校验用户、会话、画布、目标及纠正来源，保存临时理解；此时没有新任务身份或执行权限。
2. 主 Agent 可以正常回答、读取资料、加载适用 Skill。准备阶段 `update_design_brief` 仅在内存记录理解，不更新已保存任务。
3. 提出画布/设计修改、图片/视频生成、模板应用或专家委派时，使用本轮已冻结的同一模型做一次独立、无工具、非流式的短审核。
4. 审核读取真实用户原文及来源标记、最近会话、有效任务原文、当前对象及明确选中信息。Skill、摘要、主 Agent 的 brief 和参数不能自行构成授权。
5. 服务端再核对实际对象、定位选择、数量和精确拟执行范围。单数有多个同等候选时不能猜一个或批量；明确多对象必须匹配完整集合。
6. 核对通过后重读证据，确认未变化，再以数据库 compare-and-swap 激活。任务激活与旧方案失效在同一事务内；激活成功才中止被纠正的旧运行。实际工具仍保留费用、权限、版本、删除确认等检查。

### 图片引用与目标

读取 Logo 作为参考，不等于修改原 Logo，更不等于写入旧画板。独立生成的实际目标和只读来源分开核对；当前附件或真实单选可以定位参考图。库存中“存在某图片”不能自动证明用户想使用它。

消费已冻结图片方案时不激活另一个任务，避免在确认前把该方案作废。明确产品确认仍沿原有鉴权、费用及方案版本流程执行。

### 前端和并发

- ACK 仅代表收到运行请求，不伪造任务 ID 或 revision；只有可信 GET 返回该 run 的已保存任务后才更新任务卡。
- 普通无限画布发送时捕获真实 `canvasSelection`，前后端都核对属于当前画布且未删除。主模型和审核模型使用同一份明确选择；不根据“这个”猜 ID。
- 活动运行按画布保存集合。咨询结束能恢复之前仍执行的运行；恢复还必须匹配聊天 `sessionId`，不跨聊天混入消息。
- 停止发生在审核、激活等待期间时，返回后再次检查取消，不继续调用实际写入工具。
- 纯文字操作可将真实选中的容器映射到唯一、互相一致的绑定文字；混合操作、缺失或冲突绑定不猜测。

## 仍未通过的部分与边界

- 合法的“只改画板尺寸、不缩放对象”仍被真实模型不必要地追问，这是尚未解决的语义过拦。
- 明确抠图的审核原答表示 allow，但 selector 的未知字段导致格式校验失败。证据只确定错误位置，未保留该未知字段名称，不能断言具体字段就是根因。
- 复验之后补充了 `selected/all_objects.value` 的安全兼容：即使存在该字段也直接丢弃，绝不据此改向；其他未知字段仍拒绝。此兼容和容器文字投影只有离线验证，**未追加实模复验**。
- 最终 gate SHA-256：`1851999FD327DCF536FAAF90CDC707D09342EE7D4FBC9FB2D352DFFCA5A96890`；与实模复验的 gate hash 不同，不能混为同版本实测。
- 审核允许只是解除一层否决，不新增付费、删除、权限或版本授权。格式错误、超时、过期目标会阻止执行，而非偷偷换模型或自动重试。
- 每轮最多 8 次独立写入审核，达到额度会明确说明后续未执行。视频子 Agent 的不透明 `task` 入口被阻止，视频仍可使用主 Agent 的 `generate_video`。
- 原文只读取有界近期片段并标明早文省略；如依赖未提供的旧约束，不能宣称已完整理解。超过证据预算或对象观察上限也不会默默截断后执行。
