# Agent 意图审核剩余问题修复与复验

## 范围与历史

本轮继续修复上一份 `agent-intent-write-boundary-20260909.md` 未通过的两个问题：合法的仅画板尺寸修改被过度澄清，以及明确抠图的审核格式兼容。沿实际调用链还发现并修复图片方案确认时资源身份丢失的断点。

旧 24 例、旧 8 例复验的预期、分数和失败记录不改写。本轮数据、调用账本和结果在 `artifacts/intent-write-remaining-20260909/` 单独保存。

## 根因与改动

### 1. 把对象歧义错误套到画板属性

真实 `canvas.update` 实现中，省略 `resize_mode` 或使用 `crop` / `expand` 只修改画板属性，不改变现有对象的坐标、尺寸、文字、字体或图片数据。`scale` 也只有尺寸实际变化时才等比缩放并居中对象。画板边界变化仍可能改变可见/导出范围，不能声称视觉完全不变。

旧审核只看到原始工具参数和所有图层，真实模型把多个同名标题误判为画板尺寸操作的目标歧义。本轮新增只读 `intent-effect-observation.ts`，按生产契约及执行器计算操作范围、默认尺寸语义、对象字段变化和未知项，随原始请求一并提供给独立审核器。事实不提供权限，不把任何澄清结果自动改为 allow；咨询、夹带修改、错误来源和过期版本仍经过原有核验。

### 2. 格式兼容的验证边界

上一轮只确认 selector 存在未知字段，未记录字段名，不能事后声称具体字段就是根因。既有 `selected/all_objects.value` 兼容会丢弃这个无权重字段，绝不用它定位目标；其他未知字段仍拒绝。本轮补充清晰的合法 selector 结构说明，并记录安全的格式诊断，不输出私有思考或凭据。

本轮修改前基线：同一当前模型抠图连续两次通过，尺寸连续两次误拦，合计 **2/4**，没有技术格式错误。这说明当前抠图格式路径已在实模复现中通过，不证明所有供应商输出均无误。

### 3. 图片确认保留原图身份

图片工具准备方案时会把 `inputImages` 从资源 ID 转成执行所需的 URL/data URI。原意图审核却仅按资源 ID 查找，合法的带参考图确认可能在进入模型前就被判为无法定位来源。

修复方案保留服务端验证的原图身份与执行引用绑定；审核只接收资源 ID 形式的副本，执行继续使用原冻结图片输入。来源事实仅适用于对应的同一个确认方案，不成为本轮附件、任意其他生成调用或另一个画板的授权。原权限、费用、确认、版本及来源可读性检查不被替换。

校验同时接入实际确认工具的提交前位置，覆盖 UI 快捷确认和 Agent 确认。原图权限撤销、待删除、数据变化或旧方案缺少可信绑定时不提交；仍允许取消该方案。已有任务继续走原幂等恢复/回放入口，保留 queued 恢复、成功结果及 dead_letter 终态，不重新检查旧原图或建立新任务。

原图校验复用 RLS 和 Storage 原件读取：单图上限 20 MB、每轮校验等待整体 10 秒、不自动重试。超时后不再启动后续读取，已在途的 SDK 读取不能强制中止。Agent 确认可能经历两次上下文复核加一次提交前检查，最多重复读取三次；UI 快捷确认只有提交前一次。这是当前正确性优先的性能取舍，并非零额外延迟。

### 4. 整体缩放的范围表达

新措辞测试中，模型正确理解“整板及全部内容缩放”，但返回 allow + none，与实际全体对象写入冲突而被硬校验否决。没有自动修正模型回答来放行。

进一步补充 `existingObjectWrites` / `readSourceObjects` 归一化事实，并要求实际既有对象写集合非空时使用真实对象 selector；用户允许全部内容缩放时用 all + all_objects，用户禁止缩放时仍拒绝这一参数方案。该项有独立补测，与前一版本结果分开保存。

### 5. 快捷确认的工作区模型别名

快捷确认发生在普通 Agent 模型目录加载之前，之前未传 `availableModels`。合法的 `workspace:UUID` 即便指向 `gpt-image-2`，也会被去背景验证当成不支持的型号。现使用当前用户身份读取同工作区已发布模型目录，传给确认工具解析；保留原冻结别名，不替换成上游字符串绕权限。取消不依赖模型目录读取。

真实 runtime 的离线回归覆盖：正确别名 createJob + commit、all/vip 拒绝、未发布/错误模态/目录失败拒绝、取消、已有 queued 恢复、成功结果回放及 dead_letter 终态。所有 job/Storage/模型边界使用内存替身，没有网络图片生成。

## 方法与限制

使用 OpenAI Docs 的方法区分结构合法、语义判断和实际副作用，固定预期并保留失败，而非仅看模型是否输出 allow。[结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)明确指出合法结构仍可能有语义错误；[评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)强调任务特定评测与持续回归。

保持当前服务默认 `apiyi:gemini-3.1-flash-lite`，不换模型绕过失败。在线评测仅调用文本审核模型，实际执行工具替换为内存计数器；图片提供商与真实用户画板不参与，不能把该成绩当作完整主 Agent 或图片效果端到端验收。新措辞用例预先冻结，但主线程曾检查数据构建脚本，因此不标为严格盲测。
