## 渠道与失败恢复

当前可用图片目录三项：GPT Image 2、Nano Banana 2、GPT Image 2.5 All，均为 OpenAI-compatible adapter。禁用项不算可用渠道。

**三项不同模型不是三条互为备份的连接。** 当前数据库冻结计划仅允许相同 upstream 模型的兼容连接替换；现有三个 upstream 不同，不能声称它们之间自动切换已跑通。本轮不擅自扩大到跨模型替换、迁移数据库或修改共享渠道配置。

已修复：

- Nano 原先仍继承 SDK 自动重试一次；所有图片生成/编辑现统一 client 及 per-call `maxRetries: 0`。使用真实 OpenAI SDK、拦截 HTTP 的测试证明 Nano 生成和编辑只发一次，普通 503 也不会隐式重发。
- 结构化 error_code 进入 recentJobs / get_image_status。已知拒绝、未知结果不能靠模糊助手描述混为一谈。
- Mastra dead_letter/canceled 终态幂等写回聊天卡片和画布占位符，并恢复崩溃窗口。聊天定时恢复仅处理带 mastra_submission_key 的直接任务，避免给 legacy 任务新增卡片。
- 集成时发现只重启 API 不会更新独立 worker；真实 Nano 失败卡片仍为 running 由此暴露。最终加载必须覆盖两者。复核也补上了终态恢复的 Mastra 范围限制；只读查验 legacy 新增 job-id 卡片和 chat_terminal_finalized_at 标记均为 0，没有隐藏或删除记录。

隔离覆盖包括：首连接明确拒绝后切换、全部拒绝、第二连接未知结果、取消时不继续切换、队列重投不再调用已执行供应商、存储失败只恢复存储、终态卡片持久化和 legacy 隔离。使用真实 executor / SDK 加模拟传输或内存 checkpoint，不是实际第三方多渠道故障，也不是生产扣费验收。

根因代码缺口：`reloadMessages` 无版本比较，早发晚回的历史GET能整表覆盖刚创建的assistant placeholder，后续delta按ID更新时找不到对象。修复为每session本地消息版本和reload请求版本，丢弃过期快照；不同session隔离；后续新reload仍加载权威终态。三个确定性前端测试覆盖延迟GET、持续delta、后续job结果、乱序reload与会话隔离。

重建后的真实浏览器强制竞态探针未发送请求：持有首次历史GET时WS首帧未就绪，30秒退出，sentRunCommands=0。证据 `2026-09-13T09-00-45-435Z.json`。该路径记录为不适用，不能拿单元测试或未发送探针冒充真实竞态通过。普通真实失败恢复与无刷新交付另行验收。

最终普通真实交付已在上述GPT Image 2新请求通过。强制网络竞态仍只由确定性hook/stream联合测试覆盖，不宣称真实浏览器延迟GET也已通过。测试脚本还修正了失败截图时间：DB终态后应等待前端对应job卡片变终态，再判生图失败，不能提前截图将短暂传播延迟误判永久卡死；这个新增失败等待分支仅语法检查，未再付费触发故障验收。
