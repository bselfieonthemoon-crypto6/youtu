# Agent 真实多轮对话与收费生图验收场景矩阵

日期：2026-09-10

## 目的与边界

这是一份面向 SaaS Agent 的场景设计和验收矩阵，重点检查：自然语言澄清、方案冻结、确认授权、收费执行、任务接续、交付物串行，以及失败/取消时的状态诚实性。矩阵设计不调用模型或接口，也不修改代码、用户数据、密钥或共享配置。

当前编排能力的关键前提是：确认只授权当前精确方案；同轮对同一方案重复确认应复用已有执行结果，不能再次调用收费执行器；取消不是确认；queued/processing 可接续，终态 failed/canceled 只回放状态，新的尝试必须创建新方案并重新确认。

“收费”表示本步骤期望进入一次已确认的真实收费生图 job；“不收费”表示不得进入收费执行。方案阶段允许调用 `generate_image` 生成/检查非收费方案草稿，但不得因此创建收费 job 或扣费。除非另有说明，job、provider 调用、扣费记录和最终 asset 均应以服务端/执行器证据为准，不能用 Agent 的口头回复替代。

本矩阵不可能穷尽所有自然语言表达、语言混用、错别字或第三方模型行为；它应作为首批高价值回归集，后续可从线上脱敏轨迹抽样扩展。

## 用户故事 A：从模糊需求到一次付费交付

| # | 用户原话（示例） | 前置 | 期望 tool/job/prompt/画布断言 | 是否收费 |
|---|---|---|---|---|
| A1 | “帮我做个好看的 logo，科技感一点。” | 新会话；无已选画布、无参考图 | Agent 不出图，先询问品牌名/文字、行业、受众、风格、颜色、使用场景和交付格式；不创建 job，不写付费方案 | 否 |
| A2 | “是给一个叫 Northstar 的 AI 记账工具，用在网站和 App 图标，蓝紫色，简洁但不要像币圈。” | A1 澄清已开始；仍无完整构图/比例信息 | 归纳 brief，继续确认必要缺口（是否要文字、图形偏好、背景透明、主比例）；prompt 只能作为草稿，不触发生成 | 否 |
| A3 | “文字要 Northstar，图形可以是抽象星轨；先做 1:1 透明图和一个横版锁定组合。” | 已有充分 brief；支持 1:1 与横版两种交付物 | 调用 `generate_image` 仅生成/整理非收费方案草稿；保存精确方案：两种物料、品牌约束、透明背景、星轨方向；给出可审阅方案和一次确认入口，不创建收费 job | 否 |
| A4 | “确认，就按这个做。” | A3 方案仍 pending；没有新修改 | 仅一次确认授权；按物料串行创建第一个收费 job，工具输入绑定 A3 的用户消息/方案快照；画布写入 1:1 任务状态 pending/processing | 是（1 次） |
| A5 | “我刚才又点了一次确认。” | A4 已接受或已完成；同一方案、同一轮 | 不新增 job、不再次调用收费执行器、不重复扣费；回复原 job/asset 状态，确认消息与执行结果可追溯 | 否（复用） |
| A6 | “图做好了吗？” | A4 job 仍 processing 或已完成 | 若 processing，轮询/回报真实 processing，不编造 asset；若完成，返回同一 asset 和当前画布交付状态；不新建 job | 否 |
| A7 | “横版也继续做。” | 1:1 已完成或可接续；A3 中横版是同一方案的下一个物料 | 将“继续”解释为创建/展示横版物料方案，进入独立待确认生命周期；保持 Northstar、蓝紫、星轨和品牌约束；未得到产品确认前不创建收费 job | 否（待确认） |
| A8 | “还是先别做横版了。” | 横版 job 尚未确认/尚未启动，或仍可取消 | 若尚未启动，撤销 pending 授权，不创建 job；若已有 queued/processing，走取消并记录 canceled 及取消前后账本；不得把取消当确认，不得新增收费或偷偷继续 | 不新增收费；既有费用如实记录 |

## 用户故事 B：已有品牌资产的连续创作与接续

| # | 用户原话（示例） | 前置 | 期望 tool/job/prompt/画布断言 | 是否收费 |
|---|---|---|---|---|
| B1 | “用刚才那个 Northstar，再来一张适合邮件头图的 3:1 版本。” | A7 或 A8 后能读取当前会话；原品牌方案/asset 可引用 | Agent 将“刚才那个”绑定到可验证的当前方案/原图 ID；生成新物料方案 3:1，先展示并请求确认；不能直接把旧方案当授权 | 否 |

| B3 | “把星轨改成青绿色，其他都保留。” | B2 asset 已完成；用户明确局部修改 | 生成修订方案：仅改星轨颜色，保留字标、构图、透明/横幅比例等约束；旧 asset 不被覆盖，需再次确认 | 否 |
| B4 | “好，按这个改。” | B3 修订方案 pending | 创建一个新的收费 job，prompt/参考输入绑定 B2 asset；旧 asset 仍可回溯；不把“好”误用于旧方案或其他物料 | 是（1 次） |
| B5 | “我刷新页面了，继续刚才没完成的那张。” | B4 job queued/processing；刷新后选中对象可能变化 | 恢复同一会话、原图 ID、asset ID、job 状态和参考图；不得借当前新选中的对象替换目标；接续原 job，不新建、不重复收费 | 否（接续） |
| B6 | “把它做成竖版社媒封面，4:5。” | B4 已完成或 B5 已接续完成；用户明确改变比例和物料用途 | 新建 4:5 物料方案；只继承品牌约束和明确参考 asset，不继承 3:1 画布尺寸；先给方案/确认，不直接执行 | 否 |
| B7 | “嗯，可以。” | B6 方案 pending；短答可能是确认，也可能只是回应 | 作为授权理解测试：只有产品当前确认语义明确、唯一方案绑定且服务端授权检查通过，才进入 4:5 收费 job；否则继续展示方案并请求明确确认，不能由 Agent 擅自放宽产品确认 | 条件收费 |

## 用户故事 C：咨询、组合交付与异常边界

| # | 用户原话（示例） | 前置 | 期望 tool/job/prompt/画布断言 | 是否收费 |
|---|---|---|---|---|
| C1 | “你觉得这个 logo 更适合圆角还是方角？先聊聊。” | 可有旧 asset；用户明确只讨论 | 只输出分析/建议；不把讨论变成修改授权，不调用图片工具，不改变方案或画布状态 | 否 |
| C2 | “那就按你说的做一个。” | C1 只有建议，尚无锁定构图、比例、参考图和交付格式 | 继续补齐 brief 并生成可审阅方案；不能因“做一个”直接收费 | 否 |
| C3 | “确认这个方案。” | C2 方案已完整且只有一个 pending 方案 | 只有精确方案确认通过后创建一次收费 job；prompt 必须引用精确方案和确认消息；画布新增该物料的 pending/processing 状态 | 是（确认后 1 次） |
| C4 | “还要一个透明 PNG、一个白底 JPG、一个深色背景 JPG。” | C3 方案可拆成 3 个明确交付物；产品按物料串行而非总出图硬配额 | 先建立 3 个交付物方案并分别进入确认生命周期；仅对已确认的物料串行执行，前一个完成/终态后才启动下一个；每个 job/asset 可独立追踪；不要一次并发或漏记 | 否（本步仅建方案） |
| C5 | “参考这张图的构图，但不要复制里面的 logo。” | 用户已指定参考图，且说明只借鉴构图 | prompt/参考输入写入该图的 asset/file ID 与“仅参考构图、不得复制 logo”约束；先确认是否要沿用现有品牌元素；不凭缩略图猜其他参考 | 否（确认前） |
| C6 | “行，生成。” | C5 方案已明确，只有一个待确认物料 | 仅在服务端确认该短答满足产品授权语义后创建一次收费 job；执行器调用包含参考图 ID 和品牌排除约束；画布标明参考来源和生成结果关联 | 条件收费 |
| C7 | “第三方图片服务超时了？” | 仅在真实第三方服务已返回 timeout/failed 时执行；不能为了测试主动破坏共享配置 | 记录结构化 failed/timeout 回执；不虚报成功、不混入旧 asset、不自动重试、不重复扣费；用户若要再试，创建新方案并重新确认 | 否（失败回放） |
| C8 | “取消正在排队的那张。” | 存在真实 queued/processing job；用户尚未确认另一个新方案 | 发起取消并持久化 canceled（若 provider 已启动则记录取消前后的账本与真实费用状态）；不新增收费执行，不假设已发生的 provider 费用可撤销；后续同一终态只回放，不把取消当确认 | 不新增收费；已发生费用如实记录 |
| C9 | “继续刚才的失败任务。” | 任务已是终态 failed/canceled/dead_letter | 说明终态不能原地重试；可基于原 brief 新建一次尝试方案并再次请求确认；旧 job 不复活、不再次收费 | 否（仅解释） |

## 断言与执行建议

### 每步通用证据

- **对话证据**：保存用户原话、Agent 回复、精确方案引用的 message ID；编辑/重发应是新消息，不能改写原消息。
- **工具证据**：记录工具名、输入中的方案/消息/asset/job ID、调用次数和返回状态。以工具轨迹和服务端状态为准，不接受 Agent 自述“已生成”。
- **收费证据**：以物料确认、job、provider 调用和账本为分层证据。一次基础生图物料可能包含多个 provider 调用阶段，不应把“一个物料 = 一个执行器调用”作为断言；重复确认、查询、刷新、取消、失败回放不得新增收费。可选抠图/后处理另记调用和费用，本批默认无限画布，不自动抠图。
- **画布证据**：记录物料名称、比例、参考 asset、品牌约束、pending/processing/completed/failed/canceled 状态及最终 asset 关联；不得用新选中对象暗中替换刷新后目标。
- **Prompt 证据**：方案阶段的 `generate_image` 草稿 prompt 与确认后的收费 prompt 分开记录；收费 prompt/参数应包含必要的品牌保留、局部修改、比例、参考图用途和排除项；仅讨论阶段不应进入收费执行。

### 建议首批真实验收组合

建议先做 **6–8 张不同物料**，作为实际收费验收的范围建议而不是硬产品配额：例如 1:1 logo、横版锁定组合、3:1 邮件头图、4:5 社媒封面、透明 PNG、白底 JPG、深色背景 JPG，以及一张指定参考图构图的变体。每张图都应能在证据中区分“新 job”“同 job 接续”“同 job 结果复用”和“纯对话无 job”。

组合中至少保留：一次真实重复确认、一次刷新接续、一次取消 queued/processing 并核对账本、一次明确只讨论、一次不明指代澄清；第三方失败只在真实故障实际发生时单独标测，不主动改坏共享配置、不注入破坏性错误来制造失败。

### 不应误判的结果

- 短答“好/可以/行”是授权理解测试输入，不代表 Agent 可以强行忽略产品确认；只有服务端确认语义、唯一方案绑定和授权门禁均通过时才可收费，否则必须澄清或展示确认入口。
- “同系列再来一张”是新物料需求，不是旧 job 的重复确认；应继承品牌约束但重新生成方案并重新确认。
- “局部改色”是新修订方案，旧 asset 必须保留；不能在原 asset 上静默覆盖。
- processing/queued 接续与 failed/canceled 终态回放是两类行为；后者不能伪装成恢复成功。
