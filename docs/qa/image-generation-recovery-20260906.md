# 生图任务恢复与回归

## 本次证据

画布 0560072c-5c8a-4954-b037-9b476246a671 的原任务 6aaae7f6-fd96-4659-bece-89e89c527ceb 已由 queued 进入 running，但执行进程曾消失而 watch 包装进程仍存在。未获取到原进程完整退出堆栈，不能把某个异常推断为已证实的唯一触发原因。

修复过程中原任务依既有队列恢复规则第二次领取并成功，无另建任务。已核验 Storage 图片实际可下载、PNG 可解码，画布仅有一个对应的非删除图片节点，聊天结果为“图片生成完成”，队列消息已移除。原请求是否曾在供应商侧计费无法从本地记录确定，不能承诺供应商侧恰好执行一次。

## 修改

- 队列异步任务立即附加异常处理，覆盖领取、计数及失败处理本身抛错的情形；释放并发容量。基础设施异常不擅自重置状态、不新增任务，保留消息供现有状态机恢复。
- 运行日志确认存在任务行已不存在的孤立队列消息。读取返回明确 job_not_found 时归档消息；数据库查询故障仍保留消息，不误归档。该路径此前位于异常保护之外。
- 开发环境直接监督实际 Worker 子进程，退出后 1～30 秒退避重启；主动停止不重启。Worker 不再随代码文件修改立即重启，修改 Worker 代码后需重启开发服务。API 仍保留 watch。
- 后续图片任务在存储前读取文件真实尺寸，不直接使用供应商声明的尺寸。此次实际文件为 1536×1024，旧任务记录为 1024×1024；没有擅自修改用户既有画布布局或裁切结果。读取真实尺寸不保证供应商遵从请求的宽高比。

## 检查范围

68 项 Vitest 用例与 3 项 Node supervisor 用例通过；后者包括真实 Node 子进程退出再启动。服务端类型检查通过。

覆盖确认前不发起生成、扣费与发布顺序、取消领取拦截、任务状态转换、结果恢复与幂等插入、设计画板最终回写、图片数据与真实尺寸、异步异常隔离。原任务为真实模型与 Storage 链路验证，没有为测试额外创建付费生图任务。

## 边界

这是针对本次生图故障的回归，不是整个项目无缺陷保证。生产部署仍需进程管理器或容器 restart 策略及告警；开发监督器不覆盖直接启动 worker 命令的生产服务。既有过期 running 任务领取阈值仍为 30 分钟；未知供应商结果的重试不具备外部 exactly-once 保证。
