# Agent 生图五项修复与验收

日期：2026-09-09。范围：Agent 生图/改图、图片任务交付、前景去背景、视觉核验、Skills 与提示词编排。没有新增 Qwen 分层方案，也没有修改用户现有画布内容。

## 1. 异步交付与恢复

- 画板目标任务不再通过外层画布恢复接口插入错误位置。
- 图片生成成功与应用到设计的状态分开；应用失败/需要处理时保留图片并收口聊天状态，不把它显示成仍在生成。
- 服务端恢复查询先过滤目标错误、已删除/待删除/缺失资源及不完整结果，再排序与限量，避免历史坏数据长期占满恢复批次。
- 应用前再次检查资源生命周期；恢复复用原任务与素材，不重新调用生图模型。
- 未入队任务中途退出后，按真实 canonical `target` 恢复同 ID 节点和任务标记；保留拖动位置，已删除节点不复活。已有任务恢复不依赖当前模型目录，若任务已消失也不会新建替代任务。

## 2. 用户意图与参数约束

- 模型选择、原图身份和编辑比例在创建方案时固定，确认时再次校验。
- 编辑默认使用已认证原图的真实比例；改变比例需要明确的 resize 意图，不能受画板尺寸或历史任务影响。
- 不接受未绑定到本轮附件的历史 URL 或任意外链作为真实原图。
- 修改需求重新创建方案；旧确认不能偷偷改变提示词、模型、原图或目标。
- 内部 origin/source 字段贯穿持久化归一化，公开接口不能伪造这些字段。

## 3. 真实像素核验与如实交付

- `screenshot_canvas` 实际读取截图像素给视觉模型检查；仅得到 URL 不再算“看过图片”。
- `review_image_results` 可以读取当前工作区素材、只读提示词案例，也可以按 `job_id` 找回当前图片任务的成功结果；跨工作区、会话、画布、来源或旧任务不接受。
- 核验与准确的任务版本、job 和 asset 绑定；原图不能冒充生成结果，旧 job 不能覆盖新结果的验收。
- 文字内容变化需要视觉复核，不能只因文档保存成功就宣称显示正确。
- 单次核验最多 4 图、每图 8 MiB、总量 24 MiB、完整链路 20 秒超时；失败/不可用如实返回，不触发自动重生成。
- 异步结果和聊天卡明确标记“尚未视觉验收”。确认任务的快速路径仍异步返回，worker 完成后**没有后台自动调用视觉模型**；后续 Agent 可只读检查结果。该边界不能与“每一张图都已自动检查”混淆。

## 4. gpt-image-2 API 前景处理

- 显式去背景只接受准确的 `gpt-image-2`，排除 `-all`、`-vip` 和本地兜底。
- 画板背景图直接交付；前景使用 gpt-image-2 时一次请求透明 PNG，不再重复抠图。
- 用户选其他生图模型时保留主模型，另用 gpt-image-2 去背景；两阶段模型、调用次数和总积分均进入冻结方案与确认卡。
- 主生图和去背景分别冻结供应商凭据与价格快照，全部准备完整后才能扣费/入队。重复确认不会多扣费或重复入队。
- 任务创建与快照写入之间退出时，只能为尚未计费/入队的任务补齐快照；已有快照不受当前模型配置变化影响。数据库提交会锁定画布并验证待生成节点，缺失节点 ID、已删除或错绑的节点不能绕过检查扣费。
- 原图与去背景结果分别做持久化检查点；上传重试优先恢复已有结果。供应商结果未知时停止自动重发付费请求。
- 实际输出检查 PNG 和非全透明/非全不透明 alpha，不能把普通图片或假透明当作成功。
- API 重绘去背景可能改变主体细节；上述逻辑不能保证像素级还原，也不能让第三方服务永不失败。

## 5. Skills、提示词库与最终方案

- 以真实 Agent 工具图执行 Skills 编排、案例检索和方案持久化，断言最终冻结提示词、原文案、模型、目标与报价，而非仅检查工具名称。
- 覆盖逐字提示词、Logo、轮播图一致风格、用户纠正覆盖旧方向、歧义澄清、案例只作方法参考不暗加原图。
- 限制搜索摘要的模型上下文体积，选定完整提示词后折叠旧搜索列表；完整已选提示词、Skill 指令和来源保持不变，原始历史不被修改。
- 这些任务级测试使用离线脚本模型，因此验证的是编排和约束，不是实际模型的理解能力得分或成图审美质量。
