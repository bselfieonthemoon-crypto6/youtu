# 管理后台 B4b：技能图片接到用户侧（2026-09-20）

B4 的后半：把平台管理员维护的封面与示例图，展示在**用户侧**的技能卡与技能详情里。
B4a（`docs/admin-console-b4a-20260920.md`）已经把表、函数、后台界面与客户侧只读接口做完并实测，
本批只动前端 + 一个批量读取接口。

## 一、为什么需要一个批量接口

技能列表一屏可能有十几个技能，如果每张卡各自请求一次 `/api/skills/:slug/previews`，
一次列表渲染就是十几个请求。所以新增：

- `GET /api/skill-previews?slugs=a,b,c`（登录即可）
  → `{ groups: [{ slug, cover: 预览|null, examples: [预览] }] }`
  - slug 列表**去重、过滤非法值、最多 50 个**（超过或为空一律 400）
  - 只返回 `published`；**只有草稿的技能不会出现在结果里**（而不是返回一个空组）
  - 单次查询就取完"技能 → 已发布图片 → 素材"三层，图片签名失败的行直接跳过
- 原来的单 slug 接口保留（详情页/其他调用方），实现改为复用同一个分组逻辑，避免两套代码漂移。

## 二、用户侧展示

- **技能卡**（`components/skills/skill-card.tsx`）：有封面时在卡片顶部展示 16:9 封面（`loading="lazy"`，
  点击进入详情）；没有封面时保持原来的紧凑外观——**这张图是可选的，两种状态都必须像是有意设计的**。
  底部补一句"N 张示例"作为进入详情的提示。
- **技能详情**（`components/skills/skill-detail-dialog.tsx`）：新增「技能效果图」区块：封面大图 +
  示例图网格（带说明）；底部固定一句**"效果图由平台维护，仅作能力示意，不代表你的实际生成结果"**——
  避免把平台的示例读成对用户产物的承诺。没有已发布图片时整个区块不渲染。
- **技能页**（`app/(workspace)/skills/page.tsx`）：按当前可见（筛选后）的技能 slug **一次批量拉取**，
  slug 列表排序后作为依赖键，避免每次渲染重复请求；**图片读取失败只影响图片**（清空图片、列表照常可用）。

## 三、验证

- 服务端新增/扩展：`admin-skill-service.test.ts`（+2 例：批量分组把封面与示例分开、只含草稿的技能缺席、
  无法签名的行被跳过；slug 列表去重/去非法/上限裁剪）与 `admin-skills.test.ts`
  （+1 例：批量端点返回各技能分组、空列表与超过 50 个一律 400）。
- Web 新增 `test/skill-previews.test.tsx`（6 例：卡片有封面时渲染图片并显示示例数、无封面时保持原样且其余功能仍在、
  详情渲染封面 + 每张示例（含无说明的）、无图时整个区块不出现、**技能页按可见技能一次批量拉取并显示封面**、
  **图片接口失败时列表照常显示**）。
- **真实数据端到端**（`artifacts/admin-console-smoke.mjs`）：上传 → 发布 → 单 slug 客户接口可见 →
  **批量接口返回该技能的封面**（`groups[0].cover.id` 与刚发布的预览一致）→ 下架后从客户侧消失 →
  删除 → 审计 8 条 `skill.preview.*` 记录 → 清理自检素材。
- 全量：server / web 测试与两端 typecheck 全绿，编码审计干净（见提交信息）。

## 四、有意不做

- **拖拽排序 / 图片裁剪**：后台目前是上移/下移 + 原因（可测试、可审计）。
- **按技能差异化展示位**（例如给某些技能更大的展示区）：等有真实内容量后再谈。
- **市场（marketplace）列表的图片**：社区市场走的是另一套接口与数据结构，本批只覆盖技能目录/已安装列表；
  需要时把批量接口扩展到市场条目（前提是市场条目也有稳定 slug）。
