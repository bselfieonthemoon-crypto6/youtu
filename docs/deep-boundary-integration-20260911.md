# 深入边界测试：主控复核

本轮请求是测试，未修改业务实现、重启服务或操作原用户设计；新增测试和报告。两个子代理均实际配置 gpt-5.6-luna / medium，分别负责对话与上下文、WebSocket 边界。主控复核证据并重跑失败探针。

## 已复现，需优先修复

1. **P1：客户端连接 ID 碰撞导致跨用户回执错投。** 真实本地 API、两个隔离 QA 用户复现：B 使用与 A 相同的 connectionId 后，A 的 canvas.resume 回执发给 B。旧 A 关闭还会删除 B 的替换连接。主控重跑 3 个安全断言均失败。根因涉及 ConnectionManager.register 覆盖注册、按 ID 路由，以及 handler 的旧 socket close 按 ID 删除。需要服务端连接身份隔离，并将消息处理/异步回执/移除操作绑定到当前 socket 实例或代际；仅给 ID 增加随机性不足。

2. **P1：RPC 回执缺少连接归属校验。** 受控内存测试中，B 持有 A 的请求 UUID 时可以 resolve A 的 pending RPC。主控重跑亦复现。请求 UUID 已知是前提，未证明可随机猜中；未进行真实浏览器 RPC 攻击。应把 pending 绑定实际接收请求的连接及实例，拒绝其他连接或过期实例代答。

## 验收解释

主控先复跑现有 6 个 WebSocket 测试文件，20/20 通过；新增探针仍发现以上漏洞，说明旧用例不覆盖这些边界，不能以旧测试全绿推断生产安全。两个探针的重复运行不累加为新覆盖场景。

对话/上下文报告见 docs/luna-deep-boundary-tests-20260911.md。模拟像素模型的固定返回只验证输入范围和程序行为，不证明真实模型必然正确；手动调用两次视觉函数不证明自动重试编排。此前真实九图轨迹是历史证据复核，不算本轮新的供应商请求。

本轮直接查库还澄清了第9张首次失败原因：视觉模型返回 suggestions[0] 对象，而契约要求字符串，Zod 输出校验失败。此前最终回答所称“参数校验失败”不够准确，不是主 Agent 传错工具参数。该轨迹重试成功，但结构化输出恢复仍需要单独区分于工具入参校验。

本轮探针无模型/生图请求、无业务数据写入；真实登录探针会产生认证记录。团队成员撤销后的既有订阅、多进程广播、活动 run 跨租户取消、真实支付退款以及生产负载仍不能宣称已验证。代码审查发现成员移除与内存广播订阅的失效机制还需专项验证，暂不列为已实测泄露。

结论：不应判定全部边界通过。应先修复两个连接归属问题，再将失败探针改为持续回归并验证修复。
