## 接入边界

- `LOOMIC_MASTRA_MEMORY_MODE=observational` 使用新记忆；`legacy` 保留回滚入口。一轮只启用一个历史压缩实现。
- 原始对话仍由原数据库维护。使用官方 `Memory.omEngine` 与 `observe({messages})` 接受外部原始消息，不让主 Agent 自动保存包含画布快照、渠道目录、临时任务状态的整个输入。
- 观察/反思模型明确使用该轮已有的工作区聊天模型，不回退到 SDK 示例中的 Gemini。
- 工作区、用户、会话共同确定记忆身份；先经过原项目 RLS 和画布/会话/工作区校验，再访问记忆。
- 图片资产、版本关系、实际执行状态继续从业务数据库读取；记忆内容不能成为执行权限或成功回执。
- 本次不把所有品牌偏好自动提升为跨项目全局偏好，也不引入第二套 Working Memory 写入流程。

## 本地启动与回滚

先确认没有运行中的请求，再按原流程切换 API；不要停止独立图片 worker。

```powershell
./scripts/start-local-api.ps1 -AgentRuntime mastra -MemoryMode observational
```

此本地启动器只读取指定 Docker 数据库的凭据，连接 `127.0.0.1:54322/loomic_replica_light_20260907`，不输出密码，不读取远程 `.env.local` 数据库地址。正式环境须单独配置 `LOOMIC_MASTRA_MEMORY_DATABASE_URL` 并执行权限/迁移验收，不能把本地结果当生产多用户验收。

回滚使用 `-MemoryMode legacy`，不删除已有聊天或记忆记录。

### 反思路径修复与重跑

- 使用同一官方 Memory API：观察的临时实例关闭内部自动反思；观察成功后，正常实例调用公开 `reflect()`，由其重新读取刚写入的记录。未修改 node_modules，也未手改历史记忆表。
- 压缩目标和完成输出余量分开：当前目标约 2,000 tokens，完成输出最多约 6,000 tokens，避免目标本身被误当成硬截断输出上限。实际上下文仍受原字节预算控制。
- 反思失败时保留刚成功写入的新观察，返回带 reflect 阶段标签的降级上下文，不重新提交生图。
- 没有采用语义正则锚点判定用户需求；通过当前有效状态优先的原生反思指导、真实新旧值替换测试验证。
- 真实 run `6d4b1a7f-c31b-4a0b-8205-ac9af0ad236c` 无答案提示回忆六项通过，原生 generation 8 水位前进到 `2026-09-13T16:38:40.021Z`，不再回退。后续 generation 10 为 5,637 字节，开头为当前新品牌，六项和取消项保留，水位 `2026-09-13T16:39:41.422Z`。
- 默认反思曾保留过长旧项目流水，因此进一步给公开 `reflect()` 的 SPECIFIC GUIDANCE 明确紧凑当前状态，不输出逐轮日志；继续进行不复述答案的 11 轮真实复测。
- 最新针对性回归：10 文件 99 项通过，服务端 TypeScript 检查通过。含模拟传输，不能计为 99 次真实模型请求。

### 压缩频率修正

全量近期长回复可能超过原生观察阈值，但实际可压缩的旧消息很少。现改为：未超过总字节预算时，用同一原生 getStatus 再核对候选旧消息自身阈值；候选不足则不付费压缩，预算内原文照常提供。总包超字节时仍及时强制观察，不再被原生二次阈值挡住。新增两项回归后最终为 101 项。新版本两个真实图片请求均复用记忆，没有触发观察/反思。
