# 生图重要链路可靠性加固

日期：2026-09-09。范围：节点生图持久任务、生成结果恢复、原生设计验收状态。不新增 Qwen，不部署其他分层模型，不修改用户画布或模型配置。

## 节点提交与画布一致性

- 直接节点生图保留用户原文和指定模型，不自动套用风格 Skill 或改写提示词。当前节点接口仍为纯文本，参考图明确提示使用改图入口，不静默忽略。
- 前端先保存节点与冻结请求，再提交 `POST /api/jobs/node-image-generation`。请求包含稳定的 `request_id` 和明确 `canvas_id/element_id`。
- 单个数据库事务完成授权复核、模型配置快照、任务创建、积分扣除、节点绑定和队列发布。中途失败整体回滚。同一请求重复提交返回原任务，不二次入队或扣费。
- 响应不明时使用只读 `GET /api/jobs/node-image-generation/:requestId` 找回任务；不会后台重新提交。明确未提交与结果未知分开处理：前者可以修改参数再发起，后者冻结原请求并复用原 ID。
- 面板关闭不取消已提交任务。结果替换原节点 ID，采用节点当前几何位置，保留删除标记。
- 服务端提交代次 `node_submission_revision` 同时写入任务和节点。旧标签页、旧请求及提交前的草稿不能覆盖新任务或把完成图片变回待生成节点；其新位置/删除操作仍可合并。
- 任务恢复表 RLS 只允许创建者在有画布访问权限时读取，写入与事务 RPC 仅 service role 可用；RPC 重新检查实际用户与租户/画布写权限。

## 生成恢复的边界

普通图片、设计背景和需后处理的设计主体使用私有、任务绑定的 `calling → returned → archived` 存档。原子独占创建 `calling` 后才允许调用供应商；先保存供应商返回地址，再下载并保存可持久恢复的图像数据。下载、存储或本地后处理失败时，复用原结果，不重新生成。

付费 API 去背景也接入此边界，继续固定使用已有 `gpt-image-2`，不改为 all/vip。其存档阶段单独绑定 `0-foreground`，不与普通生图原图阶段混用。透明 alpha 检查失败仍明确报错，不因重试再调用付费模型。

本地后台启动时复现了历史自动恢复问题：已标记删除的素材还会被成功任务重新放回画布。恢复扫描现先批量检查主结果及分层结果所有素材的生命周期；已删除、缺失或查询失败时不写入画布。本次误恢复的 4 个旧 `Isolated job restore audit` 合成测试节点已按确切节点/任务 ID 软删除撤回，可恢复；没有修改用户画布。

上游若已受理、但在返回前断线，或返回后还未来得及持久化就崩溃，不能据此认定“没生成”。无供应商幂等键/查询能力时标记结果未知并停止，避免自动重复付费；不能保证自动找回这类结果。远程返回地址在首次下载前过期也仍是外部边界。

## 结构、保存、视觉分开验收

- 服务端记录 `technicalStatus`、`savedStatus`、`visualRequired`、`visualStatus` 和具体问题，前端按这三层状态显示。
- 布局、样式、图片、画布、对象增删排序等变化要求视觉核验，调用方的 `visual:false` 不能跳过。仅原生精确文本变更可不自动进行视觉评审。
- 视觉不可用、未执行、存在无法确认项都不是视觉通过。缺失或旧版的空核验记录不能被推断为已通过。
- 受限交付文案由服务器决定；原模型“视觉完美通过”的草稿不会广播或存入聊天。文本结构核验也不会冒充视觉验收。
- 核验期间又发生编辑，旧结果失效；按当前文档与预览版本重新检查。不会为状态更新额外生图。
- 独立图片目前如实显示尚无统一视觉验收记录；本轮没有实现独立图片的自动主观美学评审。
