# Agent 编排失败项跟进（2026-09-10）

## 本轮修复

- 隐藏旧需求卡后，运行中的普通聊天纠正入口不再被错误禁用；可输入与实际写入授权分开，发送仍校验当前任务版本。
- 自动识别的纠正与显式纠正共用启动失败恢复；失败草稿保留，新输入不会被旧请求失败覆盖。
- 刷新后仅恢复与当前任务原图 ID、asset ID 都匹配的参考，不借新的选中对象暗中改目标。
- 首次发送的简短修改、选中对象与保存时快照继续生效；明确只分析不变成对旧任务的修改授权。
- 消息先持久化再启动 run；保存失败不启动；同步启动锁消除快速双击窗口，ACK 后允许正常纠正。
- migration 11 将方案绑定精确用户消息，确认与消息写入用同一 session 行锁；用户消息正文不可变，编辑重发创建新消息。
- migration 12 为未提供 message ID 的旧 API 客户端原子创建请求消息与 run，不按相同文案猜历史；HTTP 持久化失败会取消内存 run。
- 取消不能被工具当作确认；旧确认不能跨越已提交的新纠正；重复确认保留原任务；同轮接续使用真实 run 而非随机伪造身份。
- 同轮成功保存的方案按规范化输入幂等回放，不再以不同输入覆盖；失败校验可以修正参数。当前单待确认方案生命周期按物料串行，不是用户总出图数量限制。
- 同轮对同一方案的重复确认共用执行结果，下一轮可读取/接续；不能重复调用收费执行器。
- 任务明确失败返回结构化 failed 状态、当前方案回执和中文错误说明；区分未完成任务接续与终态失败回放，不能向用户虚报已恢复生成。
- 删除按错误文本包含 `timed out` 猜测仍在生成的逻辑；真实 runtime 轮询窗口结束显式返回 processing，第三方终态超时仍为 failed，避免失败后界面继续转圈。
- 真实模型连续出现失败后混入旧交付物的错误收尾，因此改用当前工具失败回执确定性结束；经流式消息通道输出并绕过成功验收文案缓冲，不依靠再次提示模型不要编造状态。正常规划与对话仍保留流式输出。

## 真实模型评测

采用 OpenAI 官方 [Agent evals](https://developers.openai.com/api/docs/guides/agent-evals) 所建议的执行轨迹验证思路，检查真实工具动作，不用模型自述代替执行证据。

- 使用当前配置的 `apiyi:gemini-3.1-flash-lite` 文本模型及生产 DeepAgent/工具处理器。
- 方案、任务、画布与图片执行器在内存中隔离。文本模型真实调用；图片服务为 mock，不是收费生图验收。
- 历轮报告保存在 `artifacts/agent-multiturn-live/attempt-*.json`，最新结果在 `latest.json`，包括代码快照哈希、每轮工具轨迹与断言。
- 第一批暴露口头方案未冻结及评测器输出限制不匹配，随后发现新增邮件头图时重建历史方案。修复后实际 M8 只调用一次生成工具并仅保存邮件方案，没有触发防重复拒绝。
- 扩大检查到用户可见回复后，发现 M9 工具失败但模型仍要求确认。结构化失败回执和提示词约束不足以阻止其混入旧落地页，因此继续实施代码级失败收尾，而非忽略这条失败断言。
- 同时发现评测 mock 错误允许已失败 job 再次执行，而真实 runtime 会保留终态。旧报告的“失败任务恢复成功”不能作为生产能力证据。修正 mock 和断言：终态回放必须保持 failed，不能新建任务或调用执行器；queued 中断恢复由实际 runtime 测试验证。
- 最终验收 **12/12**，报告 `artifacts/agent-multiturn-live/attempt-2026-09-10T13-12-10-473Z.json`。为避免无效重复收费，复用了真实执行过的 M1–M8 前缀，并在最终实现上真实重跑 M9/M10；不是声称十轮在同一次新进程中全部重跑。报告保存前缀哈希、来源与复用标记。
- M9 耗时 24.736 秒，M10 耗时 42.526 秒。两轮最终消息 ID 均为 `image-failure-receipt-*`，证明代码级回执实际触发，而非模型碰巧答对；仅描述当前邮件头图 3:1、同一任务失败及未自动重试，没有历史落地页待确认。
- M9→M10 图片执行器调用总数保持 3，任务总数保持 3；M10 只回放原失败任务。文本模型是真实调用，图片执行器仍为严格隔离 mock。
- 最终记录包含新增失败中间件的 SHA-256；前缀与末两轮共有的产品源码哈希一致，前缀报告未包含新增中间件哈希字段，不能据此宣称整个前缀已验证该中间件的所有行为。

## 范围说明

历史未绑定精确消息的方案不能靠自由文本授权旧付费任务，可通过精确方案按钮恢复或依据当前上下文重建。测试通过不代表所有自然语言表达或第三方图像模型都已验收。

本轮未新增终态任务原地重新扣费/执行功能：failed/canceled/dead_letter 只回放终态。用户明确要求新的尝试时需依据原方案创建新任务并走确认流程，不能将查询失败状态称为重新执行。与 queued/processing 已有任务接续分开验收。

实际分工：两个 Sol/high 子代理分别处理跨模块确认一致性及真实模型隔离评测；主控处理侧栏、兼容 RPC、数据库竞态、集成与部署。没有把模型测试的计划当作执行结果。
