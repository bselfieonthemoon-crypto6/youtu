# 独立图片改图错误继承画板目标修复

## 根因

本轮附件被当作参考图片，但生成目标仍取自旧方案或 activeDesignId。generate_image 的历史目标保护没有处理“重新指定独立图片”的情况，强制新方案携带旧画板 target。于是正确的 Logo 原图被用于错误的画板背景替换，比例也继承了画板。确认弹窗没有显示冻结方案的输出位置。

## 修改

- 服务端根据本轮经过权限校验并成功读取的单张图片、明确改图需求、画布对象信息建立本轮编辑目标。明确指定画板、附带画板预览、多参考图、纯参考设计需求不自动强行切换。
- 独立图片改图优先于历史画板目标和 activeDesignId；禁止携带 design target，必须带本轮原图。未指定改尺寸时使用原图比例；新结果放在原图旁，保留原图。
- 本轮独立图片编辑禁止调用设计图层修改或模板替换工具。附件读取失败时停止，不丢弃附件后继续处理历史目标。
- 前端显式附件优先，不再自动混入旧选区图片。
- 确认弹窗显示冻结的输出位置，区分无限画布新增、画板新增图层、画板替换背景。已有确认仍执行原冻结方案，不受随后切换画板影响。
- 未回滚或改写用户之前误生成的画板内容；用户应重新指定图片生成新方案，不继续确认旧错误方案。

## 验证

- 服务端 50 项相关测试通过：目标切换、附件要求、比例、保留历史画板保护、画板修改拦截、确认与重复提交、运行模式。
- 前端 48 项相关测试通过：确认位置说明、确认弹窗、消息发送及工具展示。
- 服务端、前端 TypeScript 检查通过。
- 本地真实 Agent 使用已有画板背景对话 `6cf5e924-e28f-4950-8d91-a03ccd883bf0`，仍传入 activeDesignId，但本轮附带独立白杯图片并只说“黑色背景改为绿色”。这是与 Logo 问题相同的跨目标流程，未修改用户原会话。
- 确认前没有创建任务；新方案无 design target、带一张原图、保持 1:1。
- 唯一真实改图任务 `bdcbf720-28ad-4c02-9dcc-ea74601b8c4e` 成功，最终 target.kind=canvas。原图及新结果均持久化，画板场景与原基线一致，任务期间无设计文档写入。
- Chromium 实测通过（8.7 秒）：在同一跨目标会话再次确认，当前运行返回 succeeded；没有新增任务或重复图片；刷新后原图、新图仍可读取，画布实际渲染有图像。
- 验收脚本最初误把正常的 canvas target 也当成异常，已改成检查 target.kind。随后复用已有成功任务复核，未为此重复付费生成。
- 浏览器用例改为按本次确认的 runId 检查工具结果，避免读取 WebSocket 回放的历史 processing 事件。一次服务刚重启时的连通性失败在监听就绪后复测通过。

## 复测

在本地副本环境使用 `scripts/audit-local-agent-image-flow.mjs --resume --cross-target`。已有成功记录会跳过重复生成。浏览器刷新及重复确认检查使用 `apps/web/e2e/agent-image-replay-local.spec.ts`，设置 `LOOMIC_E2E_CROSS_TARGET=true`。

此修复针对已复现的目标串线，不承诺任意自然语言、所有模型及所有流程零故障。
