# 模板原字体一致性修复（2026-09-08）

## 原因与处理

编辑器通过 fontFaceId 下载真实字体，服务端预览/导出却只写 SVG font-family，未加载对应字体文件。因此服务器没有安装该字体时会发生替代字体渲染。

现在预览和 PNG/JPEG 导出均读取绑定 fontFaceId 的资产文件，校验工作区、发布/删除状态和嵌入许可，用 fontkit 解析原始字形并生成轮廓。按真实字宽排版，使用 Fabric 的基线/行高常量。场景仍保存可编辑文字和原 fontFamily/fontFaceId；不把设计中的文字转为图片或修改字体绑定。

绑定字体缺失、无权限、损坏或缺字时明确失败，不静默使用替代字体。未绑定字体文件的旧系统字体文字维持现有行为。单次字体限制为 32 个、合计 64 MiB。

## 真实数据验证

- 设计：4e9585ba-2f23-41d6-86aa-4fe01436511d，验证时版本 64。
- 原字体：HappyZcool-2016，faceId 9d816ae7-559e-44b1-b487-a106bd2b1157，真实 TTF 读取成功。
- 使用实际图片资产、字体文件重建 WebP 预览和 PNG 导出。
- 原页面只读浏览器测试：验证字体已加载、图片已绘制，截图对照编辑器与外层预览。
- 通过标准 renderer 和 preview commit 更新此设计的派生预览；设计 scene 哈希及 revision 均未变化。旧资产未删除；修复前文档和结果记录位于 artifacts/design-font-repair-20260908。

## 回归与范围

design-font-renderer、design-preview-renderer、design-async-worker 三组共 24 项测试通过；另进行服务端 TypeScript 检查和浏览器验证。

这次未改动 Agent、生成 API、模板内容或编辑器字体选择。复杂文字（例如混合逐字样式、双向排版等）仍需各自的专项排版验收，不能据此声称所有模板逐像素完全一致。

仅需刷新页面获取新预览。其他已存在的历史缓存不会全库重写；再次修改并保存会由新渲染器生成。
