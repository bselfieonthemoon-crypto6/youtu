# Agent 编排优化：本轮交付与验收

## 已实施

1. 图片方案解析由无条件 latest 改为当前需求时间边界：读取持久用户消息，出现后续新内容时不再把旧方案当作当前方案；只有重复确认时仍恢复同一任务。消息读取超过边界上限时拒绝猜测。
2. runtime 快捷确认、生成工具同轮接续、确认工具、方案查询与意图证据共用该边界。精确 UI confirmationId 保留指定历史任务恢复能力。
3. 尚未消费确认的比例冲突/方案失配可回到 Agent；不对已经消费或不确定提交结果自动新建收费替代任务。
4. 新增 next_deliverable 路由及 nextDeliverable 版本候选。服务端读取并验证原任务，只投递用户目标和纠正等上下文，不继承旧目标、旧批准或旧工作流。
5. 原生画板创建 v2 RPC 在事务内核验继承来源、创建新目标并保留原用户需求；相同创建请求可幂等恢复。新迁移 20260910000010 已应用到本地副本并登记。
6. 自动接续在写入结果工作流前，以及异常收尾时重新检查停止状态。没有把一次前置检查宣称为完全原子的停止屏障。
7. 更新主提示词，明确新作品不等于重置品牌任务，也不等于恢复旧作品。依据 OpenAI Docs 对自动校验和批准职责的区分，业务检查保留在服务端，而非只靠提示词。

官方参考：[Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals)。以上是本项目实现，并非官方要求使用这些具体字段。

- 代理复跑 shared 路由/协议：61/61；前端提交范围：22/22；服务端继承/创建投递：18/18（与前述套件有重叠，不累加成总数）。
- shared 构建、web 和 server TypeScript 检查通过。
- `apps/server/scripts/check-current-image-requirement.ts`：在用户指定会话的真实本地数据库上读取，验证旧宣传图不再被解析为当前落地页方案；无方案写入、任务提交或供应商调用。
- `scripts/test-agent-next-deliverable-local.mjs`：真实 PostgreSQL 事务测试。核对原始用户目标保留、新目标绑定、旧结果不继承、过期/其他用户来源拒绝、重复创建只返回同一结果。最初发现幂等重放被过早的来源版本检查阻断，修正后通过。测试用户、画板与所有业务写入均回滚；已核对测试用户不存在。
- 当前聊天侧栏完整套件仍有 14 项失败，不能宣称全仓测试通过。上述有界测试也不是任意自然语言的真实模型端到端验收。
- 最终生产构建 `.next-production-orchestration` 完成并切换到本地 3020；API 3002 健康检查通过。浏览器 smoke 验证刷新后当前历史对话恢复、比例选择保留。首次 smoke 发生在 API 尚未启动完成时而超时，服务就绪后重跑通过；没有把仅控件出现但历史仍在加载的截图当作最终验收。

## 尚未完成的架构边界

- 图片 proposal 的当前需求绑定仍是保守的时间/消息边界，尚未升级成 task → deliverable → proposal 的完整持久外键。普通插话也可能使旧方案需要重新准备。
- 当前需求读取和确认提交尚非同一数据库事务；极窄并发窗口需后续使用持久需求版本和确认 RPC 原子校验解决。
- “没有持久方案就不能询问确认”的输出状态机尚未完整实现；目前支持 Agent 回到既有口头方案补充冻结，仍需其正确调用工具。
- 尚未重跑真实收费模型、生图和多轮视觉质量验收，不能宣称全部用户意图都已理解或完整无人值守。
- 审计里的 filesystem 多租户隔离条件风险、手动只读重试的完整模型接续不在本轮改动中。

## 实际分工

- Sol / high：确认身份、幂等与可恢复错误接续。
- Sol / high：新交付物上下文、协议、原生创建事务与测试。
- 主控：提示词一致性、停止检查、真实数据库回归、交叉复核、生产构建与部署。

本轮未调用收费生图或文本模型服务。没有删除用户作品或历史对话。
