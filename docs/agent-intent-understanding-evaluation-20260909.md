# Agent 意图理解优化与实测（2026-09-09）

## 结论

本轮完成了目标绑定、连续纠正、确认边界及上下文提示的修复，并首次为这一轮意图优化运行真实文本模型诊断。**不能判定“Agent 已足够可靠地理解全部用户意图”，未通过专业 SaaS 全自动写入的语义验收。**

当前服务默认模型为 `apiyi:gemini-3.1-flash-lite`，来源为既有环境默认配置（工作区没有覆盖值）。未切换主模型、供应商、模型容量配置或图片模型。这里不是声称浏览器里每一个会话都选择了同一个模型。

本地 API 已更新至本轮代码，监听 3002，`GET /api/health` 返回 `ok:true`；Web 3020 为开发热更新。没有修改真实画板、发起图片/视频任务或变更数据库 schema。

## 已实施

### 1. 当前输入不再被旧任务机械覆盖

- 普通闲置消息使用本轮附件、选择、模型偏好与 mentions，不再因为会话里存在历史任务就全部当作纠正。
- 本轮上传图片没有画布节点 ID 时，不回落到旧画板；独立图片参考优先于不相干的选中画板。
- 活动同 run 的补充、任务卡“纠正/重绑定”和绑定任务的澄清继续原任务。输入框显示可退出的补充状态。
- 上下文按 session/task/run/revision 匹配；ACK 只有 run ID 时，仅对同一个已确认 run 一次性采用服务端任务身份。
- 会话原文未删除。普通闲置追问仍有语义历史，但需要明确“补充/纠正”才能保证旧结构化任务约束续链；不是完整的自动任务关系识别器。

### 2. 定位信息不再冒充用户授权

- 删除关键词“改/换”等触发的强制改图绑定。只有经验证的图片任务目标才进入强绑定。
- 当前打开的画板改为附在真实用户消息中的来源标注观察，不再追加第二条“本轮必须改这个画板”的虚构用户消息。
- 工具强制画板目标只接受本轮已验证的设计任务，不接受环境中仅打开的画板。
- 生图工具不再因为旧方案曾属于画板，或“不要修改设计画板”含有关键词，就阻止新附件生成独立图片。
- 保留本轮其他参考附件，不再把所有附件覆盖成旧任务唯一原图。版本、权限、冻结方案和图片源检查继续生效。

### 3. 局部约束与真实对象定位

- “对，字体别变”等可确定的完整保留补充，不再清空之前准确文案约束。
- 精确值及来源与修改范围分开记录；不把 Skill、模型 brief 或历史摘要升级为用户授权。
- 选中副标题不能被硬绑定器当作明确标题请求的目标。
- 缺少对象元数据时先允许读取真实图层；成功、同目标同版本的读取才回填定位。仍有多个候选或选择冲突时再澄清。
- 未理解的范围扩展保留原文并标记 `needs_resolution`，不自动放开写入。它目前不能靠模型 brief 自行解除，仍有保守阻挡的限制。

### 4. 确认与专业方法边界

- 服务端不再让裸“可以/好的/继续/确认”独立确认任意旧的付费生成方案。当前产品确认必须匹配 proposal ID 与 decision；文本走明确“确认生成”等指令，仍由真实方案服务检查归属、过期、版本和幂等。
- 产品确认请求不再携带旧设计任务目标、附件或生成设置，因此不在确认入口重建旧任务。
- 普通非任务聊天不再因为出现修改关键词就提前作废图片方案；旧方案替换由保存新方案、明确任务版本或取消操作负责。
- 修正主提示中“修改颜色/文案一律重新生图”的冲突，只针对尚未执行的生图方案；原生文字/布局保持原生修改。
- 区分咨询、实施、节点原文生图、仅优化提示词；保留用户模型、准确文案及未要求变化的部分。
- 自动选 Skill 是方法选择，不等于用户选择该 Skill，也不增加修改或付费权限。

## 真实模型测试

采用 OpenAI Docs 的[评测方法](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：固定数据与评分、开发集和留出集分开、保留失败样本，并把模型测试与确定性代码回归分开。未因看到失败而改写 expected。

| 测试 | 通过全部断言 | 限度 |
| --- | ---: | --- |
| 旧提示词开发集 | 9 / 24 | 真实模型，合成对话，结构化意图输出 |
| 优化后同一开发集 | 11 / 24 | 同模型、同数据、同评分；非端到端 |
| 优化后留出集 | 2 / 8 | 其中 2 次调用技术失败也保留在分母；未自动重试 |
| 实际工具定义首步探测 | 7 / 8 | 只读取 tool_calls，不执行工具 |
| 强化目标说明后首步复测 | 7 / 8 | 相同歧义问题仍失败，未隐藏失败 |

### 严格评分与实际错误要区分

独立人工审查仅用于解释，不替代原始分数：

| 开发集失败主因 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 实际业务或约束风险 | 10 | 5 |
| 评分字段表达差异 | 5 | 7 |
| 输出 schema 不合法 | 0 | 1 |

例如，只咨询标题时关注标题子节点而非父画板、将相同原文再次表示成写入、用 `image.subject` 表达 Logo 主体保留，不一定构成业务错误。因此不能把 11/24 解释成真实产品仅有这些任务能完成，也不能改评分口径声称已经全部通过。

真正剩余的失败包括：

- 有两个同等候选标题、未选中对象时，模型仍可能生成两条修改命令。实际工具首步探测重复复现；仅改提示词和工具说明没有解决。
- 原生排版/颜色修改仍可能多要一次确认。
- 结构化诊断中，模型仍可能相信摘要中的历史付费批准。当前服务端已禁止裸“继续”等独立跨过生成确认，但这不是模型已经理解正确的证明。

### 费用与隔离

- 共预留并尝试 72 次真实文本调用；70 次返回可记录答案，2 次技术失败。无自动重试。
- 返回的 usage 合计输入 415,466 tokens，输出 10,680 tokens；失败调用用量未知。未据此猜测供应商金额，实际费用以账单为准。
- 请求只包含合成设计对话/对象观察，未发送真实客户画板、图片或私有素材。
- 实际工具定义探测使用生产工具的 schema/description 子集，但不给模型任何可执行 handler。没有运行完整 Agent 图，也没有检查生成视觉质量。
- 固定已有文本端点、准确模型 ID、温度 0、单次输出上限 2,000；禁止重定向、默认禁止 tools，只有 schema 探测显式开放。
- 报告保存公开结构化答案、调用选择和用量，不保存密钥、请求头或模型隐藏推理。

## 尚未解决、下一阶段应优先处理

1. **咨询与任务激活分离**：前端 fresh 消息若仍有画板 target，会进入 `loomic_agent_task_begin`，现有 SQL 会更新任务并使旧方案失效。本轮删除了普通聊天关键词作废，但未解决这条结构化任务激活链。需要把“观察到目标”“理解提案”“实际激活写任务”拆开；确认咨询时不能先改任务状态。
2. **写入前校验歧义目标**：现有局部原生约束有确定性保护，但普通无限画布还没有覆盖通用指代的强校验。应让意图提案携带目标证据、候选与修改差异，歧义时停止写入，而不是反复追加提示词。
3. **自动任务关系与纠正解除**：普通追问的历史理解和显式任务续链现在不同；需要可验证的 continuation/correction/new-task/consultation 关系，以及可被用户纠正的范围解释，不能永远依赖点击补充按钮或未知纠正后永久等待。
4. **评测表示改进**：另建允许等价主体字段、相同值空操作及合理咨询子目标的评分版本，保留本轮固定版本作历史证据；仍需新的未参与调优的留出集。之后再做隔离真实画板写入、保存与视觉验收。
