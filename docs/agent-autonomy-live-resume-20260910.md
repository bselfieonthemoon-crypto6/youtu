### 第五轮根因与后续边界

`confirm_image_generation` 三次返回 `confirmation_unavailable`。自治图片授权和预算预留成功后仍调用普通 `loomic_decide_image`，而 runtime 为任务权限将自治工具的 `run_id` 绑定原始任务 run。proposal 的 origin 也是该 run，普通确认 SQL 因 `proposal.origin_run_id=p_run` 拒绝，具体原因 `confirmation_requires_new_turn` 被上层通用文案隐藏。

这不是模型余额或供应商网络问题。不能删除普通确认“必须来自新一轮”的保护，也不能仅伪换 run ID 绕过检查。下一步需要自治专用的原子确认路径，验证有效授权、租约 claim、实际 internal run、任务版本、来源与已预留 proposal；普通用户路径保留原保护。该修复本轮尚未实施，真实图片交付与跨画板后续验收仍未完成。
