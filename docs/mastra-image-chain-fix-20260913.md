## 修复内容

1. **执行事实**：真实任务状态进入当前上下文，历史助手描述不再作为提交依据。无写工具启动时进行一次有界语义核对，必要时一次执行恢复；写工具已经启动则不做外层自动重复提交。工具开始、结束及名称严格配对。
2. **摘要降级**：摘要异常、空值、二次超限不再直接终止正常对话；保留有界旧摘要与近期原文，显式标识遗漏。摘要生成与实际 UTF-8 字节预算对齐，长历史保留首尾修订信息。
3. **比例来源统一**：明确 UI 设置优先；识别“原 3:4 改 16:9”等修订。原生工具允许模型明确声明 resize 后为多输出选择当前输出比例，旧调用方仍默认严格处理歧义。
4. **编辑继承真实尺寸**：普通编辑从认证源图读取实际尺寸及方向，避免默认退回方图；新配套图不盲目继承源图比例。读不到源尺寸时不假设方图提交。
5. **Auto 选择**：需要参考图或受控非方形输出时，在当前发布目录内优先已适配的 GPT Image 2；保留用户明确选择。不新增虚构模型，不改渠道目录，也不是所有供应商的通用能力认证。
6. **来源回溯**：显式资产可以通过当前用户、工作区、会话和画布范围的成功任务补查；重新核验来源。最新过长需求不再被跳过后反而保留已被推翻的旧短需求。
7. **工具上下文**：每一步重新构造有界工具投影，参数默认 3KB、结果 10KB、工具调用整体 48KB（字节，不是 token）；调用和结果成对裁剪，优先保留最近工具。原始 UI 事件不裁剪。

实际连续修改还暴露了结构化协议问题：第三方 JSON 模式先要求提示中包含 JSON，随后发现原生 JSON 对象模式没有传递校验 schema。现已对执行核对、来源核对共同使用 SDK 的 `jsonPromptInjection: "system"`，保留严格 schema 校验；测试检查真实请求体是否带字段结构。
