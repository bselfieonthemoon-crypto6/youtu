# 画板完成后外层预览未更新

## 用户再次反馈后的补充修复

直接下载用户设计第 62 版已保存预览，并按同一场景重新渲染：两者均为新背景加元旦文字，证实后台位图不是旧模板。只读浏览器会话也请求了正确的预览资产并显示新内容；不能据此断言用户原会话已刷新。

在外层预览增加独立的权威文档读取：初次显示、退出设计编辑、窗口重新聚焦或页面重新可见时刷新，不依赖 Excalidraw 元素版本或 WebSocket。只读查询当前可见画板，最多 4 并发；未完成的预览有限重查，不做无限轮询。保留现有布局和用户编辑，不通过此路径改写画布。另修复资源集变更时继续使用已经撤销的 Blob URL 的短暂失效问题。

新增测试覆盖无画布变更事件仍能拿到最新预览、退出和聚焦触发刷新。浏览器回归故意将画布 GET 的设计元数据固定为旧版，验证最新设计预览仍可显示并在刷新后保持。用户实际画布的浏览器核查拦截所有 API 写请求，未改用户画布内容。

## 核查

用户画布 `38d02c58-71e0-4c2c-bb08-f011b6c37ce1` 对应设计 `4e9585ba-2f23-41d6-86aa-4fe01436511d`。只读查询时文档 revision=62、preview_revision=62、preview_status=ready，服务器画布节点也引用相同新预览资产。没有直接改用户数据。

代码链路存在三个缺口：完成按钮只等预览入队；关闭只卸载编辑器，没有确保外层刷新；画布合并只比较 Excalidraw 元素版本，可能拒收较新的设计/预览元数据。仅更新 customData 而不推进元素版本仍可能不触发 Excalidraw 变更通知，真实浏览器第一轮即复现此问题。

## 修复

- 新版内联画板完成时保存修改，轮询设计的权威预览版本（最长 60 秒），刷新外层画布后才退出；不再依赖单次 WebSocket 推送。
- 预览失败或等待超时仍保留编辑界面，文档保存成功与预览更新失败分开说明。下次重试允许重新入队，不重复执行已保存的设计命令。
- 设计文档及预览元数据按自己的版本单独合并，保留胜出元素的位置、尺寸等属性；不回退新预览，不复活本地删除节点。元数据变化时推进 Excalidraw 元素版本，确保重绘。
- 普通“保存”和 Agent 的保存绑定维持原有异步预览行为。此次等待完成逻辑作用于新版内联画板“完成”入口。
