# 图片分层与原生图层

先确认用户指的是已有画板中的真实对象，还是单张扁平图片。对象 ID、源资产与当前目标从实际工具读取，不把截图中看起来独立的元素当作已有图层。

对原生设计，inspect_design 与 get_design_objects 可以读取真实层级，再使用 manipulate_design 在用户指定范围内修改、分组或调整层序。保留字体和其他对象；单纯移动某一层不需要先拆图或重设计。

对扁平图片，选中原图使用图片工具栏的「图层拆分」。它把一张扁平图变成「修补后的底图 + 若干可独立摆放的透明元素」，现在有三条入口，都靠大模型出图，都必须先看报价再执行：

- **框选剥离**：用户拖框圈住一个元素，模型只提取框内那个元素并返回全幅透明 PNG，再把同一元素从原图移除、修补完整底图。共 2 次图片调用（1 元素 + 1 底图）。框本身就是元素标识，所以没有名字，交付层按「框选元素」命名，用户可在图层面板改名。框只用于识别与限定范围，不保证像素级精确切割。
- **全部剥离**：先用视觉模型看一次图（1 次调用）提出 2–4 个元素名，用户在对话框里确认或修改后，按名字逐个提取透明元素并修补底图，共 N+1 次图片调用。识别可能漏元素或把两个东西算成一个，所以名字必须由用户过目。

元素名称应具体，例如“左侧蛇形角色”“右侧人物”“所有标题文字”“前景金币”，因为它就是给提取模型的指令。未选择的元素保留在底图；这不是自动发现所有潜在图层。界面提交一项拆分任务，但内部需要元素数量加一次背景生成，按总量计费。透明素材会按有效像素裁成小图，并记录相对位置，原图保持不变。

当前 Agent 的 generate_image/edit_image 工具没有直接 split_layers 操作。不要发送不存在的工具参数，也不要用一次普通生图冒充多层拆分；通过真实工具栏流程执行，不声称已从 PNG 恢复原始字体、遮挡内容或 PSD。大模型可能重绘细节，底图修补是推测；要求逐像素无损时应说明限制。真实图验收还发现：多元素拆分时，生成式元素可能把它认为属于该元素的部件一起带走，而底图未必精确移除它们——所以底图必须目视检查。

此技能仍为工具栏操作与验收指导，不会安装模型或服务。阅读 [分层验收与引擎边界](references/workflow.md) 检查真实结果。分层只剩上面这两条生成式入口：本地快速拆分与专用分层服务都已下线，失败时只如实报错，不隐式换引擎。此技能仍为工具栏操作与验收指导。

只要求建议或检查时不修改对象。执行仍受当前工具、画板目标锁、用户纠正、权限和费用确认约束；技能说明不增加这些权限。
