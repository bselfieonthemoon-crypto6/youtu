# 原生比例与交付边界

## 触发与比例

本流程只处理当前用户明确允许近似的生成请求，或当前明确要求使用本 Skill 的请求。单说“适配面板”仍不构成近似授权。将用户给出的宽高转换为 `W:H`，而非把它们当作工具参数。原生尺寸解析可接受 `1:3` 至 `3:1` 的正数比例；请求的原生宽高按 16 像素网格选择，比例误差不超过 1%，不会裁切或拉伸。

不要预先承诺某一像素结果或最终比例误差。小于原生最小面积的目标仍会请求更大的原生图片；任务完成后只根据实际提交回执或结果记录报告原生宽高，并在有实际结果尺寸时再计算比例误差，明确它不是用户指定的小像素尺寸，也没有发生缩放。

## 翻倍与原生尺寸选择

保留目标像素宽高。小图按 2 的整数次幂等比放大，直到面积至少 655360 像素且短边至少 16 像素；该尺寸只是尺度参考。656×176 的参考链为 656×176 → 1312×352 → 2624×704。然后先选最接近的合法比例，再由现有分辨率档位的原生尺寸解析器选择合法像素；默认仍是 Low + 1K。不能为了追求放大参考尺寸而自动改成 2K/4K。

回执中的 `scaledTarget` 是放大参考，`nativeSize` 才是规划请求尺寸；最终图片仍以真实结果为准。翻倍不能突破 3:1 上限，也不是已经对图片做了缩放。

## 调用

新图：通过 `generate_image.aspectRatio: "W:H"` 传递选定的合法比例，并设 `aspectRatioIntent:"approximate"`，其余必填内容照常提供。不要传不存在的 `width`、`height` 参数。

编辑：只有用户明确要求把现有图改成新比例，才调用 `edit_image`，并传真实 `sourceAssetIds` UUID、`sourceUsage=edit`、选定的合法 `aspectRatio: "W:H"` 和 `aspectRatioIntent=approximate`。没有改比例要求时保留来源画幅；没有真实 UUID 时不提交。近似标记只有在本轮技能读取成功且用户允许近似时才有效；不能靠传入标记绕过校验。

界面已选比例覆盖助手推断。若其和用户允许的近似比例相冲突，先说明实际冲突，请用户选择使用界面比例还是修改界面选择。

## 无法匹配的情况

仅在本技能适用的近似授权下，超过 `3:1` 的比例采用 `3:1`，低于 `1:3` 的比例采用 `1:3`。提交前说明，不再为同一近似授权重复确认。用户要求精确尺寸或禁止改比例时不适用；普通生图流程不自动替代。

**优先：居中带 + 留白 + 裁切。** 合法画布只承载目标比例的内容，占比按比例计算，与画布像素无关：超宽时横带高占画布高 `3 / 目标比例`，超高时竖带宽占画布宽 `目标比例 × 3`。示例：`658:176 = 3.74:1` 采用 `3:1`，横带约占画布高 80%、上下各留约 10%。提示词必须要求内容只占居中带、带外留白（透明用 `background=transparent` + `outputFormat=png`），不把主体/文字拉伸铺满；回复说明“裁掉上下留白即得约 3.74:1”。这样交付后裁切即可接近精确比例，避免把 3.74:1 的构图压成 3:1。

**回退：铺满合法画幅。** 模型无法保证留白时，按 `3:1` 铺满并如实说明比例差异：`656×176` 目标约 `3.727`，相对误差 `abs(3 / (656 / 176) - 1) ≈ 19.5%`，画面会比目标更高。这里的替代误差不在 1% 内；前述 1% 只指合法请求比例与解析得到的原生尺寸。必须传 `aspectRatio:"3:1"`，提示词也采用该比例，不得同时要求原始超范围比例；继续默认 Low + 1K，只有结果回执能证明实际像素。

不要把背景、GIF、压缩、导出混入尺寸生成；这些必须有独立的当前请求和适用工具。绝不创建、写入或修改原生画板。
